# k3s-new
New k3s

## CouchDB

CouchDB runs as a standalone Argo CD application in the `couchdb` namespace.
It uses a 10Gi `moosefs-storage` volume and is exposed over HTTPS at
`couchdb.16w.eu` and `couchdb.tech.eus`.

Before syncing the application, create the `couchdb-admin` Secret in the
`couchdb` namespace with `username` and `password` keys. Keep the credentials
out of Git and store the generated password securely. The template is in
[`examples/couchdb-admin-secret.yaml`](./examples/couchdb-admin-secret.yaml).
Copy it outside the repository, replace the example password, then apply that
copy with `kubectl apply -f`. The namespace must exist first.

## Prisma

Prisma is deployed as a separate Argo CD application in the `prisma` namespace.
Its frontend and backend are exposed at `prisma.16w.eu` and `napi.16w.eu`,
respectively, through Traefik with the `crowdsec@file` middleware.

The `website` workload is also deployed in the `prisma` namespace and uses the
`prisma-db-app` connection Secret. Create `super-website-env` in this namespace
from the existing `super.env` file before syncing:

```sh
kubectl create secret generic super-website-env \
  --namespace prisma \
  --from-env-file=/mnt/mfs/16W/secrets/super.env
```

Before syncing, create the `prisma-backend-secrets` Secret with the keys shown
in [`examples/prisma-backend-secret.yaml`](./examples/prisma-backend-secret.yaml).
Copy the template outside the repository, fill in the values, and apply that
copy with `kubectl apply -f`. The `prisma` namespace must exist first. Do not
commit real credentials. `DATABASE_URL` is read from the `prisma-db-app` Secret
generated by CNPG, so it does not need to be included in this Secret.

## Authentik

Authentik is deployed at `auth.16w.eu` with its own PostgreSQL 18 CNPG cluster
and a 10Gi MooseFS volume for media. Before syncing, create the `authentik`
namespace and apply a private copy of
[`examples/authentik-secrets.yaml`](./examples/authentik-secrets.yaml) after
replacing both placeholder secrets. Do not commit real credentials.
The Traefik ForwardAuth middleware is defined in
[`traefik-middleware.yaml`](./k8s/apps/authentik/traefik-middleware.yaml) and
used by Adminer; configure a Forward Auth provider and outpost in Authentik.

## Super

The `super` stack is deployed in its own namespace. `figaro-db` is a new,
empty PostgreSQL 17 CNPG cluster; it does not reuse or import the old Compose
data directory. All persisted data uses new MooseFS PVCs rather than the old
host mounts.

Before syncing, create the `super` namespace and apply a private copy of
[`examples/super-app-secrets.yaml`](./examples/super-app-secrets.yaml).
Configure the Authentik provider's redirect URI as
`https://grafana.16w.eu/login/generic_oauth` and put its client secret in
`GF_AUTH_GENERIC_OAUTH_CLIENT_SECRET`.

CNPG generates the `figaro-db-app` Secret after the database is ready. This
stack is staged in Argo CD; it does not stop or remove the Compose services.
